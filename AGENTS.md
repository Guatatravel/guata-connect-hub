# AGENTS.md

- WhatsApp knowledge media/links are sent only when the AI tags them ([[ENVIAR_PDF/MIDIA:id]]) or the client asks and names a specific keyword — keyword-only auto-send caused off-topic files.
- Group/story/marcação offer DMs (quote, cartaz, referral): `group-offer-intake.server.ts` asks which package, confirms, then conversational briefing (origem/datas/pessoas) before handoff; skips inventing payment terms; alerts OWNER_ALERT_PHONE on humano with a short package line; citation without local wamid shows reply_preview in the panel.
- Org-wide bot pause lives on `organizations.bot_paused_at` (Meta/Ajuda); inbound then stays humano. Estimated service message count is panel outbound proxy, not Meta billing.
- Triage sidebar badge counts travel_intake rows with staff_seen_at null; opening Triagens marks them seen — keeps the badge from getting stuck.
- The panel shows a single official WhatsApp line per organization (line "descubra"); the "viagens" line is legacy — avoids duplicated channels in the UI.
- WhatsApp Embedded Signup (coexistence) exchanges the Meta code only on the server and stores the business token on whatsapp_channels line "descubra"; sending uses that saved token and phone id, and Guatá env secrets are only the fallback when the line has none — keeps META_APP_SECRET, the token and the number away from other members, and stops a deleted direct-API number from overriding coexistence. The Meta app webhook must subscribe to messages, message_echoes, smb_message_echoes, and history; `whatsapp-history.server.ts` imports past 1:1 chats into the panel without running the bot; after connect (or button on Conectar Meta), `whatsapp-coexistence-sync.server.ts` calls `smb_app_data` sync_type history and tracks progress in `whatsapp_channels.coexistence_meta`; a phone echo sets the session to human so the bot stops replying.
- Passhub credentials are stored per product (api_key_aereo/hotel/seguro/rodoviario) in passhub_settings, readable only by server code; the legacy single api_key column is deprecated — Passhub issues a separate key per module.
- Account deletion and WhatsApp disconnect live in src/lib/account.server.ts; platform admins and the official Guatá org are never deleted there — prevents locking out the platform owner.
- Unit tests use bun:test and are excluded from tsconfig — vitest is not installed.
- AI replies prefer Gemini when `GEMINI_API_KEY` is set on the server (`organization_ai_settings.ai_provider` or `AIza…` agency keys); otherwise Lovable (`LOVABLE_API_KEY`). Agency keys stay server-side; reply counter resets on day 10 (America/Cuiaba); optional `reply_cap` for non-Guatá orgs on shared keys.
- WhatsApp templates: sync/create via WABA in Conhecimento → Disparos (`whatsapp_templates`); campaigns can pick approved templates.
- Instagram is only a lead bridge: comments trigger a public reply + Direct with a wa.me link; selling stays on WhatsApp. Settings/token live in instagram_settings (server-only) — keeps one sales channel and the token off the browser.
- Instagram Facebook OAuth uses a signed HTTP-only browser cookie plus short-lived, single-use database attempts bound to user and organization; only credential-free account metadata reaches the UI — prevents CSRF, replay and cross-agency token exposure.
